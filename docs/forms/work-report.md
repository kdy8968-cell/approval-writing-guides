# 업무 보고 작성 가이드

업무의 실적, 진행 상황, 완료 결과, 조사 결과, 발생한 문제와 대응을 알릴 때 사용합니다. 보고받는 사람이 **무엇을 알아야 하는지, 판단할 일이 있는지** 먼저 정하세요.

## 작성 전에 준비하기

실제 업무·보고 목적·기간과 기존 자료를 준비합니다. 수치가 있으면 단위, 비교 기준, 잠정값 여부를 함께 확인합니다. 이미 승인된 업무 기안과 이어지는 보고라면 해당 문서를 찾습니다.

## 작성 화면에 넣기

아래는 업무 보고 입력 칸의 예시입니다. 실제 조직에서 설정한 항목 이름과 선택값을 확인하세요.

| 입력 칸 | 작성 방법 |
|---|---|
| 제목 | 업무와 핵심 결과 또는 현재 상태가 보이게 적습니다. |
| 소속 부서 | 화면에 표시된 부서를 확인합니다. |
| 어떤 보고인가요? | 실적 보고, 중간 진행 보고, 업무 결과 보고, 조사·검토 보고, 문제 발생·조치 보고, 기타 중 주된 목적 하나를 선택합니다. 결과·실적·문제 분석이 함께 필요하면 본문에 담습니다. |
| 보고 대상 업무 | 실제 업무·활동·프로젝트를 한 줄로 적습니다. |
| 보고 기간 | 보고 대상의 시작일과 종료일을 선택합니다. 특정 기준일의 현황은 양쪽에 같은 날짜를 넣습니다. |
| 보고 내용 | 핵심 결과와 필요한 판단을 먼저 쓰고, 주요 내용과 근거, 남은 확인과 후속 조치를 필요한 만큼 붙입니다. |
| 파일첨부·연관문서 | 근거 파일과 앞서 승인받은 관련 업무 기안이 있으면 화면에서 직접 연결합니다. |

## 직접 작성하기

1. 결재 도구에서 업무 보고에 해당하는 서식을 선택합니다. 네이버웍스에서는 **결재 → 문서 작성**에서 확인할 수 있습니다.
2. 제목과 보고 대상 업무를 적고, 소속 부서·보고 유형·기간을 화면에서 선택합니다. 보고 기간이 끝난 뒤 집계했다면 본문에 집계 기준 시각을 따로 적습니다.
3. 본문의 대괄호 안내를 실제 내용으로 바꿉니다. 확인된 현황과 판단 요청 유무를 먼저 적고, 후속 조치에 담당·합의된 일정·실행 확인 상태를 적습니다. 보고 목적에 맞게 목차를 조정하고 해당 없는 항목은 지웁니다.
4. 근거 파일이나 선행 결재 문서가 있으면 연결합니다. 실제 결재선과 보고 내용, 표가 제대로 보이는지 확인한 뒤 상신합니다.

가상 예시에서 대상 업무는 `작업 요청 분류 시범 운영`, 유형은 `중간 진행 보고`, 기간은 `2026-11-02–2026-11-06`입니다. “11월 6일 17시 기준 20건 중 16건 분류 완료, 4건 확인 대기입니다. 진행 상황을 공유하며 판단 요청은 없습니다.”처럼 씁니다. 남은 조치는 합의 일정과 실제 완료 확인을 구분합니다.

## BEST 사례 · 두 팀 진행 상황과 전환 판단을 함께 보고

**가상 메모**　두 팀에서 작업 요청 분류를 시범 운영했습니다. 11월 6일 17시 기준 출고팀 12건 중 10건, 생산팀 8건 중 6건의 분류가 끝났습니다. 남은 4건의 대기 이유는 아직 확인하지 못했습니다. 시범을 이틀 연장할지 팀장 판단이 필요합니다.

**AI가 먼저 확인할 질문**　두 팀이 같은 기간·기준으로 중복 없이 집계했는지, 4건이 모두 같은 사유로 대기하는지, 이틀 연장이 확정 일정인지 이번에 승인받을 안인지 확인합니다. 대상·분모가 충돌하면 어떤 집계를 사용할지 먼저 묻습니다. 대기 원인이 불명확한 경우에는 원인을 미확정으로 남깁니다.

**가상 확인 결과**　집계 범위와 중복 여부를 확인했고, 4건의 대기 상태는 확인했으나 세부 원인은 미확정입니다. 11월 9–10일 연장은 제안이며, 운영지원 담당이 11월 9일까지 분류 기준을 확인하기로 협의했습니다. 승인 시 11월 10일에 결과와 전환 가능 여부를 다시 보고합니다.

| 상단 입력 | 복사 또는 선택값 |
|---|---|
| 제목 | 작업 요청 분류 시범 진행 현황 및 이틀 연장 판단 요청 |
| 소속 부서 | 운영지원팀(가상) |
| 보고 유형 | 중간 진행 보고 |
| 보고 대상 업무 | 작업 요청 분류 시범 운영 |
| 보고 기간 | 2026-11-02–2026-11-06 |
| 파일첨부·연관문서 | 요청대장 집계표를 작성자가 연결 예정 · 연관문서 없음 |

**보고 내용**

11월 6일 17시 기준 작업 요청 20건 중 16건을 분류했고 4건은 확인 대기입니다. 대기 건을 확인할 수 있도록 시범 운영을 11월 9–10일 이틀 연장할지 판단을 요청드립니다.

| 범위 | 전체 | 분류 완료 | 확인 대기 |
|---|---:|---:|---:|
| 출고팀 | 12건 | 10건 | 2건 |
| 생산팀 | 8건 | 6건 | 2건 |
| 합계 | 20건 | 16건 | 4건 |

집계 단위는 11월 2–6일 요청대장의 중복을 제거한 요청 1건입니다. 대기 4건의 세부 원인은 확인 중입니다. 이번에 판단할 범위는 시범 연장까지이며, 운영 전환 여부는 검증 결과를 보고 별도로 판단합니다.

| 후속 조치 | 담당 | 기한·상태 |
|---|---|---|
| 대기 건 분류 기준 확인 | 운영지원 담당 | 11월 9일까지 · 협의 완료, 확인 예정 |
| 대기 건과 시범 연장 결과 보고 | 운영지원 담당 | 11월 10일 · 연장 승인 시 진행 |

**작성자 확인**　요청대장의 기간·중복 제외 기준과 팀별 합계를 확인합니다. 연장 제안과 합의된 확인 일정을 구분하고, 승인 또는 실제 확인이 이뤄진 뒤 해당 상태를 갱신합니다.

유형별 확인 질문과 추가 완성 사례는 [업무 보고 스킬과 유형 선택표](../../plugins/approval-writing/skills/work-report/SKILL.md)를 참고합니다.

본문과 소제목, 표는 [디자인 가이드](../../plugins/approval-writing/skills/work-report/references/design.md)와 [HTML 본문 기본틀](../../plugins/approval-writing/skills/work-report/assets/report-body.html)을 참고하세요.

## AI로 초안 작성하기

새 대화에 다음 요청문과 업무 메모를 붙여 넣습니다. [설치 안내](../../README.md)를 따라 스킬을 설치한 경우에는 `$work-report`와 함께 요청할 수 있습니다.

> 아래 메모를 바탕으로 업무 보고 초안을 작성해 주세요. 보고받는 사람은 [역할]이고, [무엇을 알거나 판단하면 되는지]가 목적입니다. 실제 상황과 기존 자료는 [메모·첨부]입니다. 이미 입력한 값은 [입력값]입니다. 본문의 기본 글꼴은 Sans Serif로 해 주세요. HTML 출력이면 바깥 `div`에 `font-family:sans-serif`를 지정해 주세요.

AI가 제안한 입력값과 유형은 실제 화면과 대조해 각 칸에 옮깁니다. 작성 화면에 HTML 입력 탭이 있으면 본문 코드만 붙여 넣고 Editor로 전환해 글꼴·줄바꿈·표를 확인합니다. HTML 탭을 사용할 수 없으면 “같은 내용을 Editor에 바로 복사할 수 있는 형태로 다시 작성해 주세요.”라고 요청합니다.

상태와 건수를 비교하는 짧은 표가 본문 전체 너비로 펼쳐지면, HTML 탭에서 해당 표의 `width:100%`를 `width:auto`로 바꿉니다. Editor로 돌아와 두 열과 모든 행이 표시되는지 확인합니다.

제출 전에 사실과 숫자, 잠정값, 남은 조치, 실제 첨부·연관문서를 확인하세요. 본문에는 보고 내용만 남기고 대괄호와 작성 안내는 지웁니다.

수치와 후속 조치는 가상 사례입니다. 실제 보고 유형과 Editor 표시 방식은 작성 화면에서 확인합니다.
