# 문제 발생·조치 보고 — 유형별 지침

SKILL.md가 실제 전달·판단 목적에 맞춰 참고하는 자료입니다. 사용자가 이 파일을 먼저 선택할 필요는 없습니다. 화면 주분류는 하나지만 복합 목적은 다른 지침의 필요한 절을 함께 참고해 상세를 설계합니다. [공통 인터뷰·입력·출력 기준](common-interview-output.md)의 사실·계산·민감정보·출력 분리 기준을 함께 적용합니다. 필요한 질문만 하고 명확한 사실에 대한 재승인 질문을 반복하지 않습니다.

## 언제 고르나요?

이상이나 문제가 발생해 확인 사실, 현재 영향, 즉시 대응, 원인 확인 상태와 남은 조치를 알릴 때 사용합니다. 중량 편차·출고 오류·설비 이상 등에서 원인이 아직 확정되지 않았어도 보고할 수 있습니다.

문제 발생 없이 개선 가능성을 조사하는 일이 중심이면 ‘조사·검토 보고’, 일반 진행 상태면 ‘중간 진행 보고’를 검토합니다. 소비자 클레임·VOC·안전사고 등 전용 절차가 적용되면 그 실제 경로를 확인하며 중복 보고를 임의로 늘리지 않습니다. 이 파일은 긴급 연락이나 현행 안전 대응·법적 신고를 대신하지 않습니다.

## 이 유형에서 확인할 내용

| 확인할 내용 | 질문할 내용 | 피할 오류 |
|---|---|---|
| 발생·발견 | 언제 어디서 무엇을 발견했나요? 발생·발견 시각이 다른가요? | 작성일을 발생일로 오인 |
| 확인 범위 | 무엇을 몇 개 확인했고 무엇은 아직 안 봤나요? | 표본을 전체 불량으로 확대 |
| 영향 | 실제 확인된 손실·고객·품질·재고·일정 영향은 무엇인가요? | 가능성을 확정 손실로 표시 |
| 즉시 대응 | 누가 무엇을 실제로 했고 현재 상태는 무엇인가요? | 예정된 격리·환불을 완료로 표시 |
| 원인 | 확인 사실·추정·가설·미확인은 무엇인가요? | 개인·업체 책임을 근거 없이 확정 |
| 남은 조치 | 추가 조사·복구·임시 대응·재발 방지·완료 확인은 무엇인가요? | 계획 작성만으로 종결 |

## 본문 구성

1. 현재 상황과 영향: 무엇을 발견했고 지금 무엇이 위험하거나 불명확한지 먼저 적습니다.
2. 확인 사실과 즉시 대응: 시각·대상·수량·측정 조건·실제 조치 순서를 구분합니다.
3. 원인 확인 상태: 확인된 사실, 근거 있는 추정, 검증 전 가설을 나눕니다. 미확정 원인을 그 상태로 보고합니다.
4. 남은 조치와 종결 확인: 실제 필요한 추가 조사·임시 대응·복구·재발 방지를 적고 완료 확인의 기준을 남깁니다. 담당·기한이 미정이면 그렇게 표시합니다.

원인을 모두 알아낸 뒤 보고해야 한다는 관문을 만들지 않습니다. 반대로 근거 없이 원인을 확정하거나 타인을 비난하지 않습니다. 즉시 연락할 상황은 현행 담당 경로에 알리며 보고서 완성을 연락의 선행 조건으로 삼지 않습니다. 보고 승인과 복구·재고 조정·지급·재발 방지 검증 완료를 구분합니다. 필요 없는 빈 목차는 생략할 수 있습니다.

### 측정·정정·첨부 확인

- 표본과 전체, 총중량과 순중량, 포대·용기 무게, 저울 상태를 구분합니다. 평균 표본을 전체 확정 손실로 곱해 쓰지 않습니다.
- 원기록과 정정값이 다르면 어떤 조건·계산이 바뀌었는지 확인하고 이전 기록을 임의로 삭제하지 않습니다.
- 사진·측정표·오류 로그는 실제 읽은 범위를 밝힙니다. 첨부 개수만 확인했으면 첨부가 충분하다고 단정하지 않습니다.
- 재발 방지책은 실제 원인·운영 조건과 연결합니다. 모든 문제에 추가 결재·전수 대장·이중 점검을 기계적으로 붙이지 않습니다.

원인이 확인되지 않았거나 복구가 끝나지 않아도 현재 사실·영향·대응과 남은 확인을 보고할 수 있습니다. ‘조치 보고’라는 이름 때문에 모든 조치가 완료됐다고 쓰거나 완료될 때까지 보고를 미루지 않습니다.

## 필요한 경우에만 볼 완성 예시

[가상 BEST 예시](#가상-best-예시) 절은 이 유형의 확인 질문·입력 칸 값·완성 HTML·작성자 확인을 담고 있습니다. 사용자가 완성 형태를 보고 싶거나 형식 비교가 필요할 때 참고합니다. 실제 자료가 부족할 때 예시로 사실을 대신 채우지 않습니다. 관련 없는 유형의 예시까지 일괄 읽지 않습니다.

최종 본문 단계에서는 [디자인 기준](design.md)과 [HTML 기본틀](../assets/report-body.html)을 적용합니다. 목차는 보고 내용에 맞게 바꿀 수 있습니다. 외부 참고자료의 의미와 적용 범위는 [공통 기준의 참고 자료](common-interview-output.md#참고-자료와-적용-범위)에 있습니다.

## 가상 BEST 예시

이 예시는 질문과 답변이 입력값과 본문으로 이어지는 흐름을 보여 줍니다. 목차는 실제 보고 목적에 맞게 조정합니다.

> 아래 상황과 수치, 조직명, 일정은 작성 연습을 위한 가상 예시입니다.

### 짧은 요청과 인터뷰

처음 요청: “원료 포대가 부족해서 20포 손실이라고 보고해 주세요.”

AI의 확인 질문:
1. 20포 전부 실측했나요, 일부 표본인가요? 표시 중량은 순중량인가요?
2. 포대 무게·저울 상태를 확인했나요? 실제 한 조치는 무엇인가요?
3. 확정 손실인가요, 추가 측정 전인가요? 이번에 요청할 지원·판단은 무엇인가요?

가정한 답:
- 작성 조직은 제조팀, 보고 대상은 입고 원료 포대 중량 편차다. 2026년 10월 15일 확인한 상태를 기준일 현황으로 보고한다.
- 20포 중 3포만 실측했다. 표시 순중량은 60kg, 표본의 총중량은 60.3·60.2·60.1kg, 각 포대 무게는 0.8kg이다. 예시_입고중량측정표.xlsx에 기록돼 있다.
- 계산 순중량은 59.5·59.4·59.3kg이며 저울 정확도는 아직 확인 전이다. 3포를 구분 보관했고 17포는 미측정이다.
- 재고 담당이 저울 확인과 잔여 수량 실측 일정을 운영 책임자와 협의한다. 일정은 미정이다. 전체 손실 확정이나 재고 차감은 이번에 요청하지 않는다.

### 가. 입력 칸 — 완성 예시

| 입력 칸 | 값 |
|---|---|
| 문서 제목 | 입고 원료 중량 편차 확인 보고 — 표본 3포 및 추가 측정 |
| 소속 부서 | 제조팀 — 실제 화면의 조직 확인 |
| 어떤 보고인가요? | 문제 발생·조치 보고 |
| 보고 대상 업무 | 입고 원료 포대 중량 편차 |
| 보고 기간 | 2026-10-15 – 2026-10-15 |

기준일의 확인 상태를 보고하므로 양쪽에 같은 날짜를 입력한 예시입니다. 실제 발생·발견 시각이 다르면 본문에서 별도로 적습니다. 표는 읽기용이며 실제 출력은 항목별 복사값과 설정을 나눕니다.

### 다. 작성자 확인 — 본문 밖 예시

실제 발생·발견 시각, 입고 식별값과 측정 기록이 필요한 범위에서 식별되게 보완합니다. 안전·품질 영향이 있으면 현행 담당 경로에 알립니다. 예시 파일은 실제 첨부가 아닙니다.

### 이 예시가 보여주는 점

표본 3포를 전체 20포로 확대하지 않고 측정값·계산값·원인·책임을 구분합니다. 근거 없는 손실 확정·재고 차감·업체 귀책을 만들지 않습니다. 후속 조사 계획과 실제 종결도 다릅니다.
