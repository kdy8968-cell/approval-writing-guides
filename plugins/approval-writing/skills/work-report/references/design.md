# 공통 작성·디자인 기준

실제 내용을 정리한 뒤 최종 본문을 만들 때 읽습니다. 모든 내용과 유형별 기준을 하나의 고정 목차에 끼워 넣지 않습니다. 소제목·비교표·목록은 읽는 사람이 결과·근거·남은 판단을 찾기 쉽게 사용합니다. 회사의 전결·보고 의무나 외부 브랜드 디자인 규정을 정하는 파일은 아닙니다.

## 결재 화면에서 읽히는 구성

- 첫 문단에 이번 문서의 핵심 결과나 요청을 둡니다. 판단에 필요한 기준일·금액·범위·조건을 가까이에 배치합니다. 긴 배경은 첫 문단 뒤에 둡니다.
- 소제목은 찾으려는 내용을 드러냅니다. 업무 보고는 `핵심 결과`, `근거와 기준`, `후속 조치`, 업무 기안은 `승인 요청`, `추진 근거`, `승인 후 실행`처럼 목적에 맞는 항목만 씁니다.
- 같은 단위의 수치와 상태를 나란히 읽어야 할 때는 표를 씁니다. 열 이름이나 셀에 단위를 표시합니다. 합계가 결재 판단에 필요하면 표의 항목과 합계를 근거 자료와 대조합니다.
- 첨부는 결재자가 판단할 항목 가까이에서 이름이나 용도를 안내합니다. 실제로 연결된 첨부와 작성자가 연결해야 할 자료는 각각 상태를 표시합니다.

## HTML과 표현

- 글꼴: Sans Serif 계열, font-family:sans-serif.
- 본문: 14px, 보통 굵기, 왼쪽 정렬, line-height:1.7, 글자색 #30343B.
- 소제목: 16px, 굵게, 위 여백 18px·아래 8px. 문단 아래 여백 10px.
- 강조: 핵심 결론·차이·유보 조건만 굵게. 문장 전체·모든 숫자에 강조하지 않습니다. 이모지·장식 배너·AI 메타 문구는 넣지 않습니다.
- 표: 실제 비교·상태·측정값처럼 나란히 읽을 내용에 사용합니다. 표 안 설명 문장도 필요하면 허용합니다. 긴 전문 내용을 작은 셀에 억지로 넣지 않습니다.
- 표 너비: 상태와 건수처럼 짧은 항목을 비교하는 표는 `width:auto`로 내용에 맞춥니다. 여러 열이나 긴 설명에 가로 공간이 필요하면 `width:100%`를 사용합니다. 예시를 참고할 때도 실제 표의 내용에 맞춰 너비를 선택합니다.
- 공통 표 서식: `border-collapse:collapse`, 셀 테두리 `1px solid #D9DEE5`, 셀 여백 `8px`, 왼쪽 정렬. 고정 너비·높이·가로 최소폭 금지.
- 허용 태그: div, p, h3, strong, ul, ol, li, br, table, thead, tbody, tr, th, td, 실제 근거 연결용 a. 인라인 스타일만 사용합니다.
- script, iframe, form, 버튼, 외부 폰트·CSS·추적 이미지·실행 코드, HTML 전체 문서 헤더는 넣지 않습니다.
- 화면 제목을 본문 h1으로 반복하지 않습니다. 실제 제공·확인된 근거만 연결하며 없는 주소·첨부번호를 만들지 않습니다.

## 문단, 줄바꿈과 링크

| 요소 | 권장 표시 방식 |
|---|---|
| 본문 | Sans Serif 14px, 보통(400), 행간 1.7, 왼쪽 정렬. 한 문단에는 하나의 핵심을 두고, 보통 1~3문장으로 작성합니다. |
| 소제목 | 16px, 굵게(700). 위 18px, 아래 8px. 다음 문단과 함께 읽히도록 제목 바로 뒤에 내용을 둡니다. |
| 문단 구분 | 주제·판단·담당·시점이 바뀌면 새 `<p>`를 시작합니다. 문단 아래 10px을 사용합니다. 같은 문단의 관련 문장은 이어 쓰고 화면 폭에 맞춰 자연스럽게 줄이 바뀌게 둡니다. |
| 강제 줄바꿈 | 같은 문단에서 반드시 다른 줄에 보여야 할 짧은 항목에만 `<br>` 한 번을 사용합니다. 여러 개의 `<br>`, 빈 문단, 공백·탭을 여백이나 들여쓰기로 사용하지 않습니다. |
| 순서가 있는 안내 | 서식 설명 편집기에서 목록 기호가 숨겨지는 경우 단계마다 `<p>`를 두고 `1.`, `2.`, `3.`을 실제 텍스트로 입력합니다. 일반 결재 본문의 목록은 Editor에서 기호 표시를 확인합니다. |
| 상세 가이드 링크 | `[서식명] 상세 가이드 열기`처럼 목적지와 행동을 텍스트로 드러냅니다. 실제 `<a>`에 굵기와 밑줄을 적용하고, 색상이 바뀌어도 링크를 알아볼 수 있게 합니다. |

한 문장에 하나의 중심 판단이나 행동을 둡니다. 단위·금액·날짜와 예외 조건을 해당 항목 가까이에 두고, 문장 한가운데서 화면 모양에 맞추려고 줄을 끊지 않습니다. 가로 공간이 부족하면 문장·셀 내용을 정리하고, 같은 정보가 보이도록 열 구성을 검토합니다.

### HTML 편집기 적용

본문과 소제목의 크기·행간은 이 가이드의 권장값입니다. 링크는 밑줄과 본문과 구별되는 색을 함께 사용합니다. 사용하는 편집기가 인라인 스타일을 지원하는지 확인한 뒤 붙여 넣습니다.

### 짧은 상태·건수 표 예시

```html
<table style="width:auto;border-collapse:collapse;font-size:14px;">
  <thead>
    <tr>
      <th scope="col" style="border:1px solid #D9DEE5;padding:8px;text-align:left;">분류 상태</th>
      <th scope="col" style="border:1px solid #D9DEE5;padding:8px;text-align:left;">건수</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td style="border:1px solid #D9DEE5;padding:8px;">분류 완료</td>
      <td style="border:1px solid #D9DEE5;padding:8px;">16건</td>
    </tr>
    <tr>
      <td style="border:1px solid #D9DEE5;padding:8px;">확인 대기</td>
      <td style="border:1px solid #D9DEE5;padding:8px;">4건</td>
    </tr>
  </tbody>
</table>
```

위 건수는 가상 예시입니다. 기존 짧은 표의 폭만 조정할 때는 HTML 탭에서 해당 표의 `width:100%`를 `width:auto`로 바꾸고, Editor로 전환해 두 열과 모든 행이 표시되는지 확인합니다.

## 실제 기본틀 사용

[report-body.html](../assets/report-body.html)은 위 스타일을 담은 직접 작성용 복제 재료입니다. ‘보고 요약·주요 내용과 근거·차이와 확인 필요사항·후속 조치’의 네 절과 구체적인 빈칸 안내로 시작하며, 고정된 네 절을 모두 채우라는 요구는 아닙니다. AI는 실제 목적에 맞는 소제목·표·목록과 내용으로 교체합니다. 작성자도 안내·HTML 주석·미작성 빈칸과 해당 없는 절을 제거합니다. 회사 로고·장식 배너·승인 도장·가짜 문서번호를 만들지 않습니다.

한 소제목에는 하나의 의미를 둡니다. 병렬 사실·담당·기한은 필요하면 각각 줄을 나누고 서로 다른 답을 슬래시로 뭉치지 않습니다. 짧은 단순 보고에 비교표·대안·성과지표를 억지로 추가하지 않고, 긴 전문 기록은 요약만으로 없애지 않습니다.

입력 칸의 제목을 본문에 다시 큰 제목으로 쓰지 않습니다. 입력 칸의 부서·유형·대상·보고 기간을 개요표로 반복하지 않습니다. 비교 기간·발생 시각·추출 기준일처럼 다른 의미가 있는 날짜는 필요한 곳에 남깁니다.

## 출력 직전 점검

- 본문 14px·소제목 16px·행간 1.7·색 #30343B가 실제 HTML과 설명에서 일치하는가?
- 표의 단위·범위·분모·자료 원천을 알 수 있는가? Editor에서 짧은 표는 내용에 맞고, 긴 표의 셀 내용이 잘리지 않는가?
- 근거 없는 결론·미확인 값을 채우거나 과도한 강조로 확정처럼 보이게 하지 않았는가?
- 마크다운의 별표·백틱·사용법이 실제 결재 본문에 남지 않았는가?
- 목차를 바꾸거나 코드 없는 Editor용 본문으로 바꿔도 같은 사실·수치·조건·근거가 유지되는가?
- 붙여넣기 후 Editor에서 첫 문단의 핵심 요청, 제목 계층, 숫자·단위, 표의 셀과 링크가 읽히는가?

HTML→Editor 전환과 코드 없는 대체 요청은 [공통 인터뷰·입력·출력 기준](common-interview-output.md)의 ‘네이버웍스에 넣는 방법’을 따릅니다. 실제 서비스별 복사 결과·저장된 렌더링이 같다고 미리 보장하지 않습니다.
