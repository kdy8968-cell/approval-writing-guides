# 공통 작성·디자인 기준

업무 기안·업무 협조·업무 보고·지출결의·인사·근태 신청 등 **모든 결재서식**에 적용하는 공통 기준입니다. 제목과 지정 입력란은 실제 화면의 항목명·순서·필수 조건을 따르고, 아래의 문체와 편집 규칙은 자유 본문이나 사유·설명 칸에 적용합니다. 본문 칸이 없는 서식은 지정된 항목만 채웁니다. 소제목·표·목록은 읽는 사람이 결과·근거·남은 판단을 찾기 쉽게 사용합니다.

## 결재 화면에서 읽히는 구성

- 첫 문단에 이번 문서의 핵심 결과나 요청을 둡니다. 판단에 필요한 기준일·금액·범위·조건을 가까이에 배치합니다. 긴 배경은 첫 문단 뒤에 둡니다.
- 대제목은 서식의 항목명과 순서를 따릅니다. 본문을 여러 큰 항목으로 직접 나눌 때는 `1. 목적`, `2. 배경`처럼 표시합니다. 자유 본문이 짧으면 필요한 제목만 씁니다.
- 큰 항목 아래에 주제가 여러 개라면 먼저 요지를 한두 문장으로 설명한 뒤, `① 적용 대상`, `② 운영 방식`처럼 하위 주제를 나눕니다. 소제목 뒤에 설명을 바로 붙이고, 한 주제로 충분하면 소제목 없이 한 문단으로 씁니다.
- `A안`, `B안`은 비교할 대안을 다시 지칭해야 할 때 사용합니다. `1)`, `2)`는 실행 순서가 있는 단계에 사용합니다. 특징·조건·비교 근거처럼 순서와 무관한 짧은 항목은 글머리표로 나눕니다. 같은 수준에는 한 가지 표기만 사용하고, 제목은 원칙적으로 대제목과 소제목 두 단계로 구성합니다.
- 첨부는 결재자가 판단할 항목 가까이에서 이름이나 용도를 안내합니다. 실제로 연결된 첨부와 작성자가 연결해야 할 자료는 각각 상태를 표시합니다.

## 결재 문서의 문체와 호칭

- 본문의 설명과 보고는 합니다체로 통일합니다. 확인한 사실은 “○○을 확인했습니다”, 예정된 조치는 “○월 ○일까지 ○○을 확인하겠습니다”, 협의 중인 사항은 “현재 ○○ 조건을 협의 중입니다”처럼 확인 상태에 맞는 종결어미를 씁니다.
- 작성자·소속·결재선이 이미 보이는 내부 결재는 첫인사를 생략하는 것을 기본으로 합니다. 첫 문단에서 승인받을 범위, 부탁할 행동 또는 보고할 결과를 제시합니다. 외부 수신용 본문을 겸하거나 문서만 따로 전달되어 작성자 설명이 필요할 때는 “안녕하세요. 운영지원팀입니다.”처럼 한 문장으로 인사한 뒤 바로 목적을 적습니다. 본문에서 상대를 직접 부를 필요가 있으면 확인된 직함에 ‘님’을 붙이고, 결재선은 화면의 공식 표기를 따릅니다.
- 결재 요청에는 결정 대상과 범위, 조건이나 금액 한도가 있으면 그 기준을 함께 적습니다. “검토 바랍니다”처럼 검토 대상과 원하는 행동이 모호한 문구는 무엇을 승인·검토·회신받을지 드러내도록 고칩니다.
- 후속 조치는 결정 권한과 실제 진행 순서에 맞춥니다. 비용과 조건이 협의 중이면 견적 확인·재보고·추가 승인처럼 다음 행동을 적습니다. “확정하겠습니다”는 작성자에게 확정 권한이 있고 필요한 절차를 마쳤거나, 확정의 선행 조건을 명시할 수 있을 때 씁니다.
- 제목·소제목·표의 짧은 항목은 ‘검토 중’, ‘담당 부서’처럼 간결하게 적을 수 있습니다. 완결된 본문 문장에는 메모식 종결(‘함’, ‘임’), 메신저 말투, 명령형을 피합니다.

### 결정 상태와 역할이 드러나는 표현

결재자가 판단할 안건에서는 ‘권고드립니다’보다 작성 부서가 어떤 안을 제안하는지 쓰는 편이 자연스럽습니다. 제안의 이유와 조건을 함께 적고, 실제 승인이 필요한 문장에서는 승인 대상과 범위를 밝혀 주세요.

| 상황 | 다듬기 전 | 다듬은 예 |
|---|---|---|
| 작성 부서의 추진 제안 | 공동 접수 방식을 권고드립니다. | 확인 누락을 줄이기 위해 공동 접수 방식으로 시범 운영하고자 합니다. |
| 승인 전 운영 방식 설명 | 요청을 접수하면 담당자가 검토합니다. | 접수한 요청을 담당자가 검토하는 방식으로 시범 운영하고자 합니다. |
| 관계 부서의 담당이 협의 전 | 운영팀은 점검 항목을 확정합니다. | 운영팀과 점검 항목을 함께 검토하고, 담당과 일정을 협의하겠습니다. |

이미 운영 중인 절차와 합의된 역할은 사실대로 적습니다. 승인에 따라 시행할 일은 ‘승인 후’, 별도 조건이 필요한 일은 ‘○○을 확인한 뒤’처럼 시점을 밝혀 제안과 현재 운영이 한 문서에서 섞이지 않게 합니다.

### 상황별 첫 문장과 후속 문장 예시

- **승인 요청**　“11월 23일부터 27일까지 포장 작업대 1대를 시범 운영하는 방안의 승인을 요청드립니다.”
- **조건부 검토**　“첫해 이용료 지원을 전제로 계정 추가안을 검토해 주시면 감사하겠습니다. 서면 견적을 받은 뒤 최종 부담액을 보고드리겠습니다.”
- **협조·회신 요청**　“출고팀에서 11월 20일 15시까지 품목별 실물 수량을 회신해 주시면 감사하겠습니다.”
- **결과 보고**　“11월 포장 작업대 시범 운영 결과와 후속 조치 현황을 보고드립니다.”
- **승인 후 후속 조치**　“승인해 주시면 현장과 적용 일정을 조율한 뒤, 확정 일정을 보고드리겠습니다.”

사용자가 해당 문서의 글자 크기·줄 높이·문단 간격·제목 표시를 지정했거나 직접 맞춘 서식을 보존하라고 요청한 경우 그 지정을 아래 기본값보다 우선합니다. 예를 들어 13px·추가 문단 여백 없음으로 지정한 문서를 14px·행간 1.7·문단 아래 10px로 임의 변경하지 않습니다. 작성·검수할 때 사용자 지정값과 기본값을 구분합니다.

## HTML과 표현

- 기본 글꼴은 Sans Serif입니다. 바깥 `div`에 `font-family:sans-serif`를 지정해 제목·본문·목록·표에 상속합니다. 붙여넣기로 다른 글꼴이 들어온 곳은 기본값으로 맞춥니다. 문서에 별도로 지정한 글꼴이 있으면 해당 값을 적용합니다.
- 본문: 14px, 보통 굵기, 왼쪽 정렬, line-height:1.7, 글자색 #30343B.
- 대제목·소제목의 글자 크기와 위아래 여백은 아래 ‘제목 계층, 문단과 줄바꿈’ 표를 따릅니다. 다른 작성 예시에서 여백이 다르면 본문을 만들 때 이 공통값을 적용합니다.
- 강조: 핵심 결론·차이·유보 조건만 굵게. 문장 전체·모든 숫자에 강조하지 않습니다. 이모지·장식 배너·AI 메타 문구는 넣지 않습니다.
- 표와 이미지는 아래 ‘모바일에서 목록·표·이미지 고르기’를 따릅니다.
- 허용 태그: div, p, h3, strong, ul, ol, li, br, table, thead, tbody, tr, th, td, 실제 근거 연결용 a. 인라인 스타일만 사용합니다.
- script, iframe, form, 버튼, 외부 폰트·CSS·추적 이미지·실행 코드, HTML 전체 문서 헤더는 넣지 않습니다.
- 화면 제목을 본문 h1으로 반복하지 않습니다. 실제 제공·확인된 근거만 연결하며 없는 주소·첨부번호를 만들지 않습니다.

## 제목 계층, 문단과 줄바꿈

| 요소 | 권장 표시 방식 |
|---|---|
| 본문 | Sans Serif 14px, 보통(400), 행간 1.7, 왼쪽 정렬. 한 문단에는 하나의 핵심을 두고, 보통 1–3문장으로 작성합니다. |
| 대제목 | `<h3>` 16px, 굵게(700). 첫 대제목의 위 여백은 0px, 두 번째부터 24px입니다. 아래 여백은 8px입니다. 일반 텍스트에서는 새 대제목 앞에 빈 줄 하나(줄바꿈 두 번)를 두고, 제목 다음 줄에 본문을 시작합니다. |
| 소제목 | `<p><strong>` 14px, 굵게(700). 위 여백 12px, 아래 4px입니다. 같은 주제의 설명은 제목 바로 다음 줄에 두고 빈 문단을 끼우지 않습니다. |
| 목록 | 순서가 없는 병렬 항목은 `<ul>`, 절차나 우선순위는 `<ol>`을 사용하고, 항목마다 `<li>`를 하나씩 둡니다. 기본 글머리표는 작은 채운 원(small disc)입니다. HTML에서는 하위 목록을 포함한 각 `<ul>`에 `list-style-type:disc`를 명시합니다. 목록 위 여백 0px·아래 10px·왼쪽 들여쓰기 22px, 항목 사이 4px을 기본으로 합니다. Editor에서 직접 쓸 때는 글머리표/번호 목록 버튼을 사용하고, 글머리표는 small disc를 선택합니다. |
| 문단 구분 | 요청과 대상처럼 하나의 판단에 필요한 문장은 같은 문단에 둡니다. 요청에서 배경으로, 비용 조건에서 승인 후 조치로 넘어가는 등 독자가 확인할 내용이 바뀔 때 새 문단을 시작합니다. HTML은 `<p>` 하나에 문단 하나를 쓰고 아래 여백 10px을 적용합니다. 일반 텍스트 원고에는 문단 사이에 빈 줄 하나를 둡니다. |
| 줄바꿈 | 문단 안은 화면 폭에 따른 자동 줄바꿈을 기본으로 합니다. 짧은 인용이나 같은 항목의 두 줄 표기처럼 줄 위치가 의미를 가질 때만 `<br>` 한 번을 사용합니다. 제목 사이와 문단 사이의 간격은 지정한 여백으로 조절합니다. 문단 안 행간은 1.7입니다. |
| 순서가 있는 안내 | 서식 설명 편집기에서 목록 기호가 숨겨지는 경우 단계마다 `<p>`를 두고 `1.`, `2.`, `3.`을 실제 텍스트로 입력합니다. 일반 결재 본문의 목록은 Editor에서 기호 표시를 확인합니다. |
| 상세 가이드 링크 | `[서식명] 상세 가이드 열기`처럼 목적지와 행동을 텍스트로 드러냅니다. 실제 `<a>`에 굵기와 밑줄을 적용하고, 색상이 바뀌어도 링크를 알아볼 수 있게 합니다. |

업무 기안 본문의 대제목과 소제목은 각각 한 줄에 두고 제목 글자에만 밑줄을 적용합니다. 서식에 별도 표시 지침이 있으면 해당 서식을 따릅니다. HTML에서는 제목 요소에 `text-decoration:underline`을 적용할 수 있습니다. 임시저장 후 Editor에서 다시 열어 제목의 밑줄과 문단이 나뉜 위치를 확인합니다.

한 문장에 하나의 중심 판단이나 행동을 둡니다. 단위·금액·날짜와 예외 조건을 해당 항목 가까이에 두고, 문장 한가운데서 화면 모양에 맞추려고 줄을 끊지 않습니다.

- **줄바꿈을 쓸 때**　같은 항목에서 전화번호와 운영시간처럼 각각 한 줄로 보여야 하는 짧은 정보만 줄을 바꿉니다. 같은 판단을 설명하는 여러 문장은 한 문단에 이어 쓰고 화면 폭에 따라 자동으로 줄이 바뀌게 둡니다.
- **새 문단을 만들 때**　같은 항목에서도 현재 방식에서 변경 이유로, 비용 조건에서 후속 조치로 설명이 넘어가면 한 번 줄을 바꿔 새 문단을 시작합니다. 같은 설명이 이어지는 문장은 한 문단에 둡니다. 큰 주제가 바뀌면 대제목을 추가합니다. 일반 텍스트 원고에서 대제목 앞은 빈 줄 하나를 두고, HTML에서는 대제목의 위 여백을 사용합니다. HTML에 빈 문단이나 연속 `<br>`을 넣어 여백을 만들지 않습니다.
- **같은 엔터처럼 보여도 간격이 다를 때**　문단 블록(`<p>` 또는 `<div>`)은 자체 여백을 가질 수 있고, `<br>`은 같은 블록에서 줄만 바꿉니다. 붙여넣은 내용에는 기존 여백이 따라올 수 있습니다. Editor에서 새 문단은 Enter, 문단 안 줄바꿈은 Shift+Enter를 사용해 보고 결과를 확인합니다. 간격이 다르면 HTML 탭에서 실제 태그·여백을 확인하고 같은 역할의 문단을 같은 방식으로 맞춥니다.

### 비교를 글머리표로 쓰는 예시

대안별로 같은 기준의 짧은 꼬리표를 붙입니다. 비교 대상은 굵은 소제목으로, 각 근거는 실제 글머리표로 둡니다. 아래 두 대안은 가상입니다.

**A안 · 기존 시스템 활용**

- **조회 범위**　일별 출퇴근과 근무시간을 받습니다.
- **반영 기준**　결재를 마친 뒤 월 마감 자료를 반영합니다.

**B안 · 별도 도구 도입**

- **조회 범위**　승인 내역을 포함한 리포트를 받습니다.
- **반영 기준**　월 마감 후 담당자가 파일을 반영합니다.

HTML에서 항목 아래 문장이 길어져도 글머리표의 들여쓰기를 유지할 수 있도록 실제 목록 요소를 사용합니다.

```html
<div style="font-family:sans-serif;">
  <p style="margin:12px 0 4px;"><strong>A안 · 기존 시스템 활용</strong></p>
  <ul style="margin:0 0 10px;padding:0 0 0 22px;list-style-type:disc;">
    <li style="margin:0 0 4px;"><strong>조회 범위</strong>　일별 출퇴근과 근무시간을 받습니다.</li>
    <li style="margin:0;"><strong>반영 기준</strong>　결재를 마친 뒤 월 마감 자료를 반영합니다.</li>
  </ul>
</div>
```

### HTML 편집기 적용

본문과 소제목의 크기·행간은 이 가이드의 권장값입니다. 링크는 밑줄과 본문과 구별되는 색을 함께 사용합니다. 사용하는 편집기가 인라인 스타일을 지원하는지 확인한 뒤 붙여 넣습니다. 같은 원고는 HTML 탭이나 Editor 중 사용하는 형식에 맞는 곳 한 곳에만 넣습니다. 수정할 때는 바꿀 본문을 교체하고, Editor에서 제목과 첫·마지막 문단이 각각 한 번만 나오는지 확인합니다. 임시저장했다면 저장함에서 다시 열어 문단·표·간격을 확인합니다.

## 모바일에서 목록·표·이미지 고르기

1. **문단·목록이 기본입니다.** 항목별로 조건이나 장단점을 문장으로 설명해야 하면 ‘소제목 → 같은 기준의 글머리표’로 세로로 배치합니다. 좁은 화면에서 셀이 세 줄 이상으로 길어지거나 오른쪽 열을 보려고 가로로 움직여야 한다면 목록이나 짧은 표 여러 개로 바꿉니다.
2. **표는 수치나 상태를 나란히 읽을 때 씁니다.** 금액·건수·일정·처리 상태처럼 열별 답이 짧고 같은 기준으로 비교할 때 사용합니다. 짧은 2–3열부터 시작하고, 폭은 `width:auto;max-width:100%`로 내용에 맞춥니다. 짧은 값 4열 이상을 나란히 읽어야 한다면 모바일에서도 잘리지 않고 읽히는지 먼저 확인합니다. 단위·열 제목·필요한 합계를 표시하고, 긴 텍스트는 자연스럽게 줄을 바꿉니다. 셀은 `1px solid #D9DEE5` 테두리와 8px 여백, 왼쪽 정렬, 표는 `border-collapse:collapse`를 사용합니다. 고정 폭·최소 폭이나 글자 크기 축소로 끼워 맞추지 않습니다. 전체 상세표가 증빙에 필요하면 원본을 첨부하고 판단에 필요한 핵심 수치는 본문에 남깁니다.
3. **이미지는 화면·사진·도식 자체가 근거일 때 씁니다.** 배치 변경 사진, 오류가 난 화면, 단계의 관계를 보여 주는 도식이 해당합니다. 스마트 에디터의 이미지 삽입 기능이 있으면 해당 문단 뒤에 추가하고, 필요한 부분을 잘라 모바일에서 확대 없이 알아볼 수 있게 합니다. 그림 아래에 무엇을 봐야 하는지 한 줄로 쓰고 대체 텍스트 입력을 지원하면 함께 넣습니다. 본문에 삽입할 수 없으면 파일을 첨부하고 관련 문단에서 안내합니다. 결재 범위·금액·조건·핵심 비교 결과는 본문 텍스트로 남깁니다. 긴 표를 이미지로 캡처해 붙이는 대신 핵심은 목록이나 짧은 표로 보여 주고 상세 원본을 첨부합니다.

같은 기준으로 비교할 대안은 대안을 행에, 판단 기준을 열에 두는 비교표부터 검토합니다. 대안명 열은 짧게 두고 설명 셀은 상단 정렬과 자동 줄바꿈을 적용합니다. 결정을 바꾸는 차이와 조건은 해당 셀에, 공통 전제나 긴 근거는 표 아래에 적습니다. 좁은 화면에서 오른쪽 열이나 조건이 보이지 않으면 기준을 묶어 표를 나눕니다.

흐름도를 넣을 때는 제목이나 설명에 현재 절차인지 제안인지 표시합니다. 본문과 도식에서 단계명·담당·승인이나 마감 같은 선행 조건·예외 처리 순서를 맞춥니다. 단계가 자동인지 담당자 확인이 필요한지도 같은 표현을 쓰고, 바뀐 내용은 본문 전체와 그림 설명에 함께 반영합니다.

HTML을 쓸 때도 본문은 제목·문단·목록·짧은 표로 구성하고, 사진이나 도식은 필요할 때 Editor에서 삽입합니다. 임시저장 후 다시 연 PC 화면과, 확인할 수 있다면 실제 모바일 화면에서 제목·목록 기호, 표의 오른쪽 열과 단위, 이미지 설명이 읽히는지 확인합니다.

### 짧은 상태·건수 표 예시

```html
<table style="width:auto;max-width:100%;border-collapse:collapse;font-family:sans-serif;font-size:14px;">
  <thead>
    <tr>
      <th scope="col" style="border:1px solid #D9DEE5;padding:8px;text-align:left;">분류 상태</th>
      <th scope="col" style="border:1px solid #D9DEE5;padding:8px;text-align:left;">건수</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td style="border:1px solid #D9DEE5;padding:8px;">분류 완료</td>
      <td style="border:1px solid #D9DEE5;padding:8px;">16건</td>
    </tr>
    <tr>
      <td style="border:1px solid #D9DEE5;padding:8px;">확인 대기</td>
      <td style="border:1px solid #D9DEE5;padding:8px;">4건</td>
    </tr>
  </tbody>
</table>
```

위 건수는 가상 예시입니다. 기존 짧은 표의 폭만 조정할 때는 HTML 탭에서 해당 표의 너비를 `width:auto;max-width:100%`로 바꾸고, Editor로 전환해 두 열과 모든 행이 표시되는지 확인합니다.

## 실제 기본틀 사용

[report-body.html](../assets/report-body.html)은 위 스타일을 담은 직접 작성용 복제 재료입니다. ‘보고 요약·주요 내용과 근거·차이와 확인 필요사항·후속 조치’의 네 절과 구체적인 빈칸 안내로 시작하며, 고정된 네 절을 모두 채우라는 요구는 아닙니다. AI는 실제 목적에 맞는 소제목·표·목록과 내용으로 교체합니다. 작성자도 안내·HTML 주석·미작성 빈칸과 해당 없는 절을 제거합니다. 회사 로고·장식 배너·승인 도장·가짜 문서번호를 만들지 않습니다.

한 소제목에는 하나의 의미를 둡니다. 병렬 사실·담당·기한은 필요하면 각각 줄을 나누고 서로 다른 답을 슬래시로 뭉치지 않습니다. 짧은 단순 보고에 비교표·대안·성과지표를 억지로 추가하지 않고, 긴 전문 기록은 요약만으로 없애지 않습니다.

입력 칸의 제목을 본문에 다시 큰 제목으로 쓰지 않습니다. 입력 칸의 부서·유형·대상·보고 기간을 개요표로 반복하지 않습니다. 비교 기간·발생 시각·추출 기준일처럼 다른 의미가 있는 날짜는 필요한 곳에 남깁니다.

## 출력 직전 점검

- 날짜·시간·수량 범위는 en dash(–) 또는 부터·까지로 기록하고 물결표를 범위 기호로 쓰지 않습니다. 완성 본문에 의도하지 않은 취소선이 없는지 확인합니다.
- 사용자 지정 서식이 있으면 그 값을, 없으면 기본 글꼴 Sans Serif, 대제목 16px, 소제목·본문 14px, 행간 1.7, 색 #30343B를 적용했는가? 대제목의 위 여백과 하위 항목의 표시가 각 수준에서 일관되고, 제목이 다음 설명과 붙어 있는가?
- 목록이 실제 글머리표나 번호로 표시되고 기본 글머리표가 작은 채운 원(small disc)인가? 문단 간격과 같은 문단 안의 줄 간격을 각각 확인했는가?
- 표의 단위·범위·분모·자료 원천을 알 수 있는가? 좁은 화면에서 표의 오른쪽 열과 숫자가 잘리지 않고, 이미지에 담긴 판단 근거도 본문에서 읽을 수 있는가?
- 근거 없는 결론·미확인 값을 채우거나 과도한 강조로 확정처럼 보이게 하지 않았는가?
- 마크다운의 별표·백틱·사용법이 실제 결재 본문에 남지 않았는가?
- 목차를 바꾸거나 코드 없는 Editor용 본문으로 바꿔도 같은 사실·수치·조건·근거가 유지되는가?
- 붙여넣기 후 Editor에서 첫 문단의 핵심 요청, 제목 계층, 숫자·단위, 표의 셀과 링크가 읽히는가?

HTML→Editor 전환과 코드 없는 대체 요청은 [공통 인터뷰·입력·출력 기준](common-interview-output.md)의 ‘네이버웍스에 넣는 방법’을 따릅니다. 실제 서비스별 복사 결과·저장된 렌더링이 같다고 미리 보장하지 않습니다.
