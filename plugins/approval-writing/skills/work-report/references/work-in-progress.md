# 중간 진행 보고 — 유형별 지침

SKILL.md가 실제 전달·판단 목적에 맞춰 참고하는 자료입니다. 사용자가 이 파일을 먼저 선택할 필요는 없습니다. 화면 주분류는 하나지만 복합 목적은 다른 지침의 필요한 절을 함께 참고해 상세를 설계합니다. [공통 인터뷰·입력·출력 기준](common-interview-output.md)의 사실·계산·민감정보·출력 분리 기준을 함께 적용합니다. 필요한 질문만 하고 명확한 사실에 대한 재승인 질문을 반복하지 않습니다.

## 언제 고르나요?

진행 중인 업무의 현재 상태, 완료한 일, 대기·지연·막힌 부분과 필요한 지원을 알릴 때 사용합니다. ERP 구축·PI 추진처럼 실제 적용과 효과 확인이 아직 끝나지 않은 업무가 해당합니다.

한 업무를 마친 결과가 중심이면 ‘업무 결과 보고’, 실적 숫자의 현황·차이 자체가 중심이면 ‘실적 보고’를 검토합니다. 완료한 일부와 남은 부분이 함께 있어도 중간보고 한 건에서 구분할 수 있습니다.

## 이 유형에서 확인할 내용

| 확인할 내용 | 질문할 내용 | 피할 오류 |
|---|---|---|
| 현재 단계 | 검토·협의·설정·시험·시범·실제 적용 중 어디인가요? | 설계·시험을 운영 완료로 표시 |
| 완료 근거 | 어떤 조건으로 무엇을 확인했나요? 기록이 있나요? | 문서 존재를 개선 완료로 계산 |
| 남은 일 | 진행·대기·지연·미착수는 무엇인가요? | 모든 미완료를 지연으로 표시 |
| 의존·영향 | 무엇이 막혔고 다음 일에 어떤 영향이 있나요? | 미회신을 동의·거절로 해석 |
| 일정 | 원래 일정과 현재 예상은 무엇이며 합의됐나요? | 희망일을 확정 일정으로 바꿈 |
| 지원·판단 | 자료·검토·자원·일정 중 필요한 것이 무엇인가요? | ‘검토 바랍니다’만 남음 |

## 본문 구성

1. 현재 상태: 어디까지 왔으며 중요한 막힘이 무엇인지 먼저 적습니다.
2. 완료한 일과 남은 일: 업무에 필요한 단위로 단계·근거·상태를 표시합니다. 실행·검증·교육·정착은 서로 다른 상태입니다.
3. 막힌 부분과 영향: 대기 이유, 연결 업무, 확인된 임시 대응을 설명합니다. 다른 부서의 의도를 추측하지 않습니다.
4. 다음 조치와 지원·판단 요청: 기존 합의된 일, 제안 단계의 담당·일정, 이번 결정을 구분합니다.

진행률은 전체 범위와 계산 기준이 실제로 있을 때만 씁니다. 시험 12개 중 9개 완료가 전체 프로젝트 75% 완료라는 뜻은 아닙니다. 회의 횟수·문서 수·설정 수를 실현 효과로 바꾸지 않습니다. 지연이나 지원 요청이 없으면 억지로 만들지 않습니다. 필요 없는 빈 목차는 생략할 수 있고 전문 진행 내용을 유지합니다.

매주 쓰거나 처리 건수가 있다는 사실만으로 실적 보고로 고정하지 않습니다. ERP 진행 단계·의존·막힘이 중심이면 중간 진행을 주분류로 두고, 실적표 기준이 필요하면 해당 지침의 필요한 절을 함께 참고합니다.

## 여러 팀의 진행 상황과 판단 요청이 함께 있을 때

팀별 집계 기간·대상·단위와 중복 처리 방식이 같은지 확인합니다. 예를 들어 출고팀 12건과 생산팀 8건을 합산하려면 같은 요청이 양쪽에 중복되지 않는지 먼저 확인합니다. 분모나 완료의 정의가 다르면 합산 가능 여부를 묻고 팀별 값을 유지합니다. `분류 완료`와 `운영 전환 완료`처럼 다른 상태는 각각 적습니다.

기준일에 확인된 현황, 이미 합의한 조치, 결재자가 이번에 판단할 사항을 구분합니다. 시범 연장이 제안이라면 시작·종료일과 연장 범위를 확인하고, 승인 후 할 일을 조건부로 표시합니다. 근거와 무관한 원인·완료 예정일은 추가하지 않습니다.

## 필요한 경우에만 볼 완성 예시

[가상 BEST 예시](#가상-best-예시) 절은 이 유형의 확인 질문·입력 칸 값·완성 HTML·작성자 확인을 담고 있습니다. 사용자가 완성 형태를 보고 싶거나 형식 비교가 필요할 때 참고합니다. 실제 자료가 부족할 때 예시로 사실을 대신 채우지 않습니다. 관련 없는 유형의 예시까지 일괄 읽지 않습니다.

최종 본문 단계에서는 [디자인 기준](design.md)과 [HTML 기본틀](../assets/report-body.html)을 적용합니다. 목차는 보고 내용에 맞게 바꿀 수 있습니다. 외부 참고자료의 의미와 적용 범위는 [공통 기준의 참고 자료](common-interview-output.md#참고-자료와-적용-범위)에 있습니다.

## 가상 BEST 예시

이 예시는 질문과 답변이 입력값과 본문으로 이어지는 흐름을 보여 줍니다. 목차는 실제 보고 목적에 맞게 조정합니다.

> 아래 상황과 수치, 조직명, 일정은 작성 연습을 위한 가상 예시입니다.

### 짧은 요청과 인터뷰

처음 요청: “연동 테스트가 75% 끝났다고 중간보고를 써 주세요.”

AI의 확인 질문:
1. 75%는 전체 구축 진척인가요, 시험 항목 중 완료 개수인가요?
2. 어떤 환경에서 무엇을 확인했고 남은 시험은 왜 대기 중인가요?
3. 다음 일정·담당이 합의됐나요? 필요한 지원이나 결정이 있나요?

가정한 답: 작성 조직은 시스템운영팀이고 보고 대상 업무는 업무시스템 연동 시험이다. 2026년 10월 16일 현재 상태를 기준일 현황으로 보고한다. 예시_연동시험기록.xlsx에서 격리 시험 12개 중 9개가 예정 결과와 일치함을 확인했고 운영 적용은 아직 안 했다. 2개는 공급사 회신 대기, 1개는 시험 계정 권한 확인 중이다. 회신 기한과 재시험 날짜는 미정이다. 운영 부서가 시험 계정을 확인하기로 했다. 신규 예산·인력 결정은 요청하지 않는다.

### 가. 입력 칸 — 완성 예시

| 입력 칸 | 값 |
|---|---|
| 문서 제목 | 업무시스템 연동 시험 중간보고 — 미완료 3개 항목 확인 |
| 소속 부서 | 시스템운영팀 — 실제 화면의 조직 확인 |
| 어떤 보고인가요? | 중간 진행 보고 |
| 보고 대상 업무 | 업무시스템 연동 시험 |
| 보고 기간 | 2026-10-16 – 2026-10-16 |

기준일 현황이므로 같은 날짜를 양쪽에 넣은 예시입니다. 실제로 전체 작업 기간의 보고라면 그 실제 기간을 입력합니다. 위 표는 읽기용이며 실제 출력은 항목별 복사값과 선택·달력 설정을 나눕니다.

### 다. 작성자 확인 — 본문 밖 예시

실제 시험 환경과 12개 항목의 범위·완료 기준을 확인합니다. 계정 권한·회신 대기 내용을 운영 반영 완료로 바꾸지 않습니다. 예시 원자료는 실제 첨부가 아니므로 실제 파일을 연결합니다.

### 이 예시가 보여주는 점

완료 개수와 전체 진척을 구분하며 미회신을 동의나 거절로 처리하지 않습니다. 결과 미측정 상태에서 실현 효과를 만들지 않고 정하지 않은 담당·기한도 임의로 넣지 않습니다.
