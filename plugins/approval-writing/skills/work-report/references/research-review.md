# 조사·검토 보고 — 유형별 지침

SKILL.md가 실제 전달·판단 목적에 맞춰 참고하는 자료입니다. 사용자가 이 파일을 먼저 선택할 필요는 없습니다. 화면 주분류는 하나지만 복합 목적은 다른 지침의 필요한 절을 함께 참고해 상세를 설계합니다. [공통 인터뷰·입력·출력 기준](common-interview-output.md)의 사실·계산·민감정보·출력 분리 기준을 함께 적용합니다. 필요한 질문만 하고 명확한 사실에 대한 재승인 질문을 반복하지 않습니다.

## 언제 고르나요?

자료나 현장을 조사해 특정 질문에 답하고 판단에 도움이 되는 결론을 전달할 때 사용합니다. 채널별 수익성, 상품 진열 변경 효과, 운영 대안 비교처럼 자료·방법·한계가 중요한 보고가 해당합니다.

실적 현황·차이의 공유 자체가 중심이면 ‘실적 보고’, 행사·출장 자체의 수행 결과가 중심이면 ‘업무 결과 보고’, 발생한 이상에 대한 조사·대응이 중심이면 ‘문제 발생·조치 보고’를 검토합니다. 결과 보고 안에 필요한 분석을 넣을 수 있으며 분석이라는 말만으로 자동 분리하지 않습니다.

## 이 유형에서 확인할 내용

| 확인할 내용 | 질문할 내용 | 피할 오류 |
|---|---|---|
| 조사 질문 | 무엇을 알아보거나 비교하려는 조사인가요? | 숫자만 나열하고 목적이 없음 |
| 자료·범위 | 기간·채널·품목·표본·원자료가 무엇인가요? | 부분 자료를 회사 전체로 일반화 |
| 비교·계산 | 단위·분모·세금·할인·비용 정의가 같나요? | 다른 기준의 비율·이익 비교 |
| 확인 결과 | 실제 자료에서 확인한 차이가 무엇인가요? | 계산과 해석 혼합 |
| 한계·가정 | 누락·잠정·동시 변경·표본 제약이 있나요? | 상관관계를 인과 효과로 단정 |
| 활용·추천 | 지금 말할 수 있는 것과 추가 확인은 무엇인가요? | 분석이 곧 정책·가격·발주 승인 |

## 본문 구성

1. 조사 질문과 핵심 결론: 무엇을 확인했고 어디까지 말할 수 있는지 먼저 적습니다.
2. 자료와 방법: 대상·원천·계산·표본 조건을 설명합니다. 입력 칸의 보고 기간은 반복하지 않되 비교 기간·자료 추출일은 필요한 의미가 있으므로 남길 수 있습니다.
3. 확인 결과: 실제 비교표·수치·관찰을 충분히 남깁니다. 사실·계산·해석을 구분합니다.
4. 해석의 한계와 다음 판단: 단정할 수 없는 이유, 추가 확인, 추천·대안과 별도 결정 범위를 적습니다.

자료가 없는데 예시 숫자로 채우거나 효과가 확인되지 않았는데 긍정 결론으로 바꾸지 않습니다. 비교 대안·시나리오 개수를 정해 놓고 억지로 채우지 않습니다. 복잡한 분석을 1페이지로 잘라내지 않으며 본문 핵심과 상세 자료를 이어 줍니다. 필요 없는 빈 목차는 생략할 수 있습니다.

### 수익·효과 분석 추가 기준

- 수익 분석은 실제 원가·세금·정산·인건비·운송비·수수료 등 포함 범위를 먼저 확인합니다. 특정 채널의 공식을 모든 거래에 일괄 적용하지 않습니다.
- 같은 ‘매출’이라도 주문·결제·취소 후·정산 기준을 섞지 않습니다. 자료에 없는 값을 추정해 합치지 않습니다.
- 전후 비교에는 기간·영업일·상품·단가·할인·노출·고객 구성 등 동시 조건을 확인합니다. 같은 일수만으로 비교 조건이 같다고 보지 않습니다.
- 비율 변화는 상대 증가율과 퍼센트포인트를 구분합니다. 10%에서 12%는 2%포인트 차이이며 ‘20%포인트 증가’가 아닙니다.
- 관찰 결과를 원인 입증으로 바꾸지 않으며, 표본·누락·가정 때문에 판단이 달라질 수 있는 범위를 설명합니다.

라이브 여러 회차의 자료로 채널 지속 여부를 판단하려는 경우 조사·검토를 주분류로 두고 실적·결과 지침의 필요한 절을 함께 참고할 수 있습니다. 화면 주분류 하나가 다른 분석·운영 근거를 배제하는 것은 아닙니다.

## 필요한 경우에만 볼 완성 예시

[가상 BEST 예시](#가상-best-예시) 절은 이 유형의 확인 질문·입력 칸 값·완성 HTML·작성자 확인을 담고 있습니다. 사용자가 완성 형태를 보고 싶거나 형식 비교가 필요할 때 참고합니다. 실제 자료가 부족할 때 예시로 사실을 대신 채우지 않습니다. 관련 없는 유형의 예시까지 일괄 읽지 않습니다.

최종 본문 단계에서는 [디자인 기준](design.md)과 [HTML 기본틀](../assets/report-body.html)을 적용합니다. 목차는 보고 내용에 맞게 바꿀 수 있습니다. 외부 참고자료의 의미와 적용 범위는 [공통 기준의 참고 자료](common-interview-output.md#참고-자료와-적용-범위)에 있습니다.

## 가상 BEST 예시

이 예시는 질문과 답변이 입력값과 본문으로 이어지는 흐름을 보여 줍니다. 목차는 실제 보고 목적에 맞게 조정합니다.

> 아래 상황과 수치, 조직명, 일정은 작성 연습을 위한 가상 예시입니다.

### 짧은 요청과 인터뷰

처음 요청: “진열을 바꿨더니 구매율이 20% 올랐다고 보고해 주세요.”

AI의 확인 질문:
1. 구매율은 상품이 포함된 영수증 비율인가요, 방문 인원 대비 구매 인원인가요?
2. 전후 기간·원자료 범위와 할인·가격·판매 조건은 같았나요?
3. 차이를 보고하나요, 진열 유지나 확대를 판단받으려 하나요?

가정한 답:
- 실제 작성 조직은 매장지원팀이다. 보고 대상은 리테일 상품 진열 변경 검토이며 보고 범위는 2026년 9월 1~28일이다.
- 비교는 전후 각 14일이다. 전은 9월 1~14일, 후는 9월 15~28일이다. 예시_POS진열비교.xlsx에 전체 영수증 1,000건·1,100건, 해당 상품 포함 영수증 100건·132건이 정리돼 있다.
- 방문 고객 수는 없다. 변경 후 할인 행사도 있어 진열만의 영향은 분리하지 못했다.
- 현재 배치를 유지하면서 할인 종료 후 추가 관찰하는 방향을 검토받고 싶다. 관찰 기간은 협의 전이며 다른 지점 확대는 요청하지 않는다.

### 가. 입력 칸 — 완성 예시

| 입력 칸 | 값 |
|---|---|
| 문서 제목 | 리테일 상품 진열 변경 검토 보고 — 구매 영수증 비중과 비교 한계 |
| 소속 부서 | 매장지원팀 — 실제 화면의 조직 확인 |
| 어떤 보고인가요? | 조사·검토 보고 |
| 보고 대상 업무 | 리테일 상품 진열 변경 검토 |
| 보고 기간 | 2026-09-01 ~ 2026-09-28 |

읽기용 표입니다. 실제 출력은 항목별 복사값과 선택·달력 설정을 나눕니다. 표 전체를 본문에 붙이지 않습니다.

### 다. 작성자 확인 — 본문 밖 예시

실제 비교 날짜·영업일·집계 정의·할인 조건을 확인합니다. 채택 후 누가 언제 관찰할지는 소관과 연결하되 임의 확정하지 않습니다. 예시 파일은 실제 첨부가 아니므로 실제 원자료를 연결합니다.

### 이 예시가 보여주는 점

비율의 분모와 퍼센트포인트를 구분하고, 효과 원인을 입증하지 못했으면 관찰·추천을 나눕니다. 보고에 새 판단이 포함돼도 어느 범위의 판단인지 분명히 남깁니다.
