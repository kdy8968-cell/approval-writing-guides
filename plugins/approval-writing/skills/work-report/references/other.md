# 기타·목적 확인 — 유형별 지침

SKILL.md가 실제 전달·판단 목적에 맞춰 참고하는 자료입니다. 사용자가 이 파일을 먼저 선택할 필요는 없습니다. 화면 주분류는 하나지만 복합 목적은 다른 지침의 필요한 절을 함께 참고해 상세를 설계합니다. [공통 인터뷰·입력·출력 기준](common-interview-output.md)의 사실·계산·민감정보·출력 분리 기준을 함께 적용합니다. 필요한 질문만 하고 명확한 사실에 대한 재승인 질문을 반복하지 않습니다.

## 언제 고르나요?

어떤 보고인지 모르거나 앞의 다섯 유형에 바로 맞지 않을 때 사용합니다. 기타를 골랐다는 이유로 반려하거나 모든 유형의 내용을 한꺼번에 작성하게 하지 않습니다. AI가 실제 목적을 듣고 가장 가까운 유형을 추천합니다.

맞는 유형이 끝내 없으면 기타를 유지하고 목적에 맞는 구성을 제안합니다. 분류를 잘 고르는 것 자체가 새 업무가 되지 않도록 이미 있는 자료·답변을 먼저 활용합니다.

## 목적을 확인하는 순서

| 확인할 내용 | 먼저 묻는 질문 | 처리 |
|---|---|---|
| 실제 전달 목적 | 어떤 일을 했거나 무엇을 확인했고, 읽는 사람이 무엇을 알거나 판단하면 되나요? | 작성자 말로 목적 확인 |
| 시점 | 마친 일인가요, 진행 중인가요, 앞으로 할 일의 허락을 받으려 하나요? | 결과·중간 상태·새 계획 구분 |
| 자료 | 메모·원자료·작성한 문서·실제 결정 기록이 있나요? | 이미 아는 답은 다시 묻지 않음 |
| 유형 후보 | 목적에 가장 가까운 유형과 그 이유는 무엇인가요? | 명확하면 추천 후 작성, 중요한 애매함만 확인 |
| 별도 경로 | 전용 서식·긴급·보안 절차가 적용되나요? | 실제 경로만 확인, 새 관문 임의 생성 금지 |

## 분류할 때 참고할 기준

- 실적 보고: 정기·비정기·일회성 여부와 관계없이 실제 실적과 중요한 차이를 파악하는 것이 주목적.
- 중간 진행 보고: 진행 중인 업무의 현재 단계·막힌 점·지원이 주목적.
- 업무 결과 보고: 행사·출장·방문·교육·회의 등 한 일을 마친 결과가 주목적.
- 조사·검토 보고: 자료·현장을 살펴 특정 질문에 답하거나 대안을 검토하는 것이 주목적.
- 문제 발생·조치 보고: 발생한 이상·문제의 사실·영향·대응·남은 확인이 주목적.
- 기타 — 유형 확인이 필요해요: 아직 판단할 정보가 부족하거나 맞는 유형이 없는 상태.

화면에서 고를 주된 유형 하나와 참고지침 수를 구분합니다. 복합 목적이면 관련 지침의 필요한 절을 함께 참고해 분석·결과·후속 판단을 담습니다. 예를 들어 출장 중 품질을 조사했다고 출장 결과와 분석을 반드시 두 건으로 나누지 않습니다. 회의 결과에 다음 협의가 남았다고 모든 회의를 중간보고로 분류하지 않습니다. 제목보다 실제 전달 목적을 먼저 봅니다.

## 유형 확인 후 작성

1. 가장 가까운 유형과 이유를 짧게 추천합니다. 명확하면 별도 재승인 질문 없이 이어 작성하고 중요한 애매함만 확인합니다. 다른 자료가 있다면 확인한 답을 보존하며 필요한 질문만 이어 갑니다.
2. 유형이 정해지면 화면의 ‘어떤 보고인가요?’ 값도 맞추도록 안내합니다. 유형 선택이 실제 변경됐다고 AI가 주장하지 않습니다.
3. 유형별 필요한 내용만 채웁니다. 실적은 집계·비교 기준, 중간 진행은 단계·의존·남은 일, 결과는 실제 수행·관찰·합의·활용, 조사는 질문·자료·방법·한계, 문제는 발생·영향·대응·원인 확인을 중심으로 씁니다.
4. 목적이 여전히 기타라면 ‘핵심 내용 → 실제 근거·경과 → 필요한 후속’ 정도에서 시작해 내용에 맞게 조정합니다. 빈 목차·모든 유형의 항목을 억지로 합치지 않습니다.
5. 신규 계약·채용·구매의 허락을 처음 받는 일이 중심이면 실제 전용 경로를 확인합니다. 보고라는 명칭만으로 이를 완료한 결과로 쓰지 않습니다. 소규모 후속 판단까지 무조건 새 기안을 요구하지 않습니다.

자료가 충분치 않으면 유형을 임의 확정하고 긴 완성본을 만들지 않습니다. 사용자가 확인 전 초안을 원하면 확인 전임을 본문 밖에 표시하고 미확인을 유지합니다.

## 필요한 경우에만 볼 완성 예시

[가상 BEST 예시](#가상-best-예시) 절은 이 유형의 확인 질문·입력 칸 값·완성 HTML·작성자 확인을 담고 있습니다. 사용자가 완성 형태를 보고 싶거나 형식 비교가 필요할 때 참고합니다. 실제 자료가 부족할 때 예시로 사실을 대신 채우지 않습니다. 관련 없는 유형의 예시까지 일괄 읽지 않습니다.

최종 본문 단계에서는 [디자인 기준](design.md)과 [HTML 기본틀](../assets/report-body.html)을 적용합니다. 목차는 보고 내용에 맞게 바꿀 수 있습니다. 외부 참고자료의 의미와 적용 범위는 [공통 기준의 참고 자료](common-interview-output.md#참고-자료와-적용-범위)에 있습니다.

## 가상 BEST 예시

이 예시는 질문과 답변이 입력값과 본문으로 이어지는 흐름을 보여 줍니다. 목차는 실제 보고 목적에 맞게 조정합니다.

> 아래 상황과 수치, 조직명, 일정은 작성 연습을 위한 가상 예시입니다.

### 유형을 고르는 인터뷰

처음 요청: “물류업체랑 회의한 내용을 보고해야 하는데 어떤 유형인지 모르겠어요.”

AI의 첫 질문: “마친 협의 내용을 공유하려는 건가요, 계약 조건을 새로 승인받으려는 건가요? 회의에서 정해진 내용과 남은 내용을 아는 범위에서 알려 주세요.”

가정한 답: 회의는 끝났고 거래 조건·계약은 이번에 결정하지 않는다. 출고 인계에 필요한 자료를 논의했다. 발주번호·상품코드·수량·희망 출고일을 전달 항목으로 쓰자는 의견은 양쪽이 확인했다. 전달 시각과 적용 날짜는 협의 중이다.

AI 추천: “완료한 회의에서 확인한 내용과 남은 협의를 보고하는 것이므로 ‘업무 결과 보고’가 가까워 보입니다. 이 유형으로 정리할까요?”

가정한 확인 답: “네. 현업 출고 담당이 후속 협의를 하지만 적용 날짜는 미정입니다.”

AI는 이미 답한 내용을 다시 묻지 않고 남은 필수 입력만 확인합니다.

추가로 확인한 가정 답:
- 작성 조직은 매장지원팀, 보고 대상 업무는 출고 인계 항목 협의다.
- 2026년 10월 16일 마친 회의 결과이므로 보고 기간은 10월 16일 하루다.
- 예시_출고인계협의메모.md에 확인 항목과 미합의 항목이 남아 있다.
- 실제 연동·시스템 구축은 하지 않았으며 전사 규칙 제정이나 계약 조건 변경은 이번 범위가 아니다.
- 예외 발생 시 연락 방법도 후속 협의할 항목이다.

### 가. 입력 칸 — 완성 예시

| 입력 칸 | 값 |
|---|---|
| 문서 제목 | 출고 인계 항목 협의 결과 보고 — 전달 시각·적용일 추가 협의 |
| 소속 부서 | 매장지원팀 — 실제 화면의 조직 확인 |
| 어떤 보고인가요? | 업무 결과 보고 — 인터뷰에서 변경 방향 확인 |
| 보고 대상 업무 | 출고 인계 항목 협의 |
| 보고 기간 | 2026-10-16 – 2026-10-16 |

기타에서 업무 결과 보고로 바꾸기로 확인한 예시입니다. 맞는 유형이 없는 다른 업무는 기타를 그대로 유지할 수 있습니다. 표는 읽기용이며 실제 출력은 항목별 복사값과 선택·달력 설정을 나눕니다.

### 나. 보고 내용 — 완성 HTML 예시

```html
<div style="font-family:sans-serif;font-size:14px;line-height:1.7;color:#30343B;">
<h3 style="font-size:16px;font-weight:700;margin:18px 0 8px;">1. 협의 결과</h3>
<p style="margin:0 0 10px;">물류업체와 출고 인계 시 필요한 자료 항목을 논의했습니다. 전달 항목은 양쪽이 확인했으나 전달 시각과 적용 날짜는 아직 협의 중입니다. 신규 거래 조건·계약 승인은 이번 보고의 범위가 아닙니다.</p>
<h3 style="font-size:16px;font-weight:700;margin:18px 0 8px;">2. 확인한 내용과 남은 사항</h3>
<ul style="margin:0 0 10px;padding-left:22px;list-style-type:disc;"><li>확인한 전달 항목: 발주번호, 상품코드, 수량, 희망 출고일.</li><li>추가 협의: 전달 마감 시각, 실제 적용 날짜, 예외 발생 시 연락 방법.</li><li>회의 기록에서 확인한 범위만 반영했습니다. 실제 출고 연동이나 새 시스템 구축이 완료된 것은 아닙니다.</li></ul>
<p style="margin:0 0 10px;">자료: 예시_출고인계협의메모.md. 계약 조건 변경이나 전사 운영 규칙을 확정한 기록과는 구분합니다.</p>
<h3 style="font-size:16px;font-weight:700;margin:18px 0 8px;">3. 후속 협의</h3>
<p style="margin:0 0 10px;">현업 출고 담당이 전달 시각·적용 날짜·예외 연락 방법을 추가 협의할 예정입니다. 적용 날짜는 협의 결과를 확인하기 전까지 확정 일정으로 안내하지 않습니다.</p>
</div>
```

### 다. 작성자 확인 — 본문 밖 예시

화면의 ‘어떤 보고인가요?’도 확인한 업무 결과 보고로 선택합니다. 상대방과 내부 회사가 어디까지 합의했는지 원기록으로 확인하고 미회신을 동의로 처리하지 않습니다. 예시 기록은 실제 첨부가 아닙니다.

### 이 예시가 보여주는 점

유형 선택을 작성자의 숙제로 남기지 않고 질문으로 목적을 확인합니다. 기존 답을 보존하며 마친 회의·남은 협의·계약 승인을 구분합니다. 추가 확인 없이 부서·날짜·담당·파일을 창작하지 않습니다.

이 예시의 유형 확인 질문은 처음 목적이 모호한 상황을 설명합니다. 실제 목적이 명확하면 유형·이유를 짧게 추천한 뒤 재승인 질문 없이 작성합니다.
