# 결재 작성 인터뷰와 출력 기준

서식별 가이드와 함께 적용합니다. 예시의 값은 가상입니다. 선택·동의·상신·승인·처리 상태는 사용자가 확인한 자료와 구분해 기록합니다.

## 서식과 요청을 먼저 정합니다

| 메모에서 확인할 목적 | 먼저 읽을 가이드 | 서식 선택을 바꾸는 공백 |
|---|---|---|
| 결정받거나 실행 범위를 바꾸기 | [업무 기안](guides/company/work-proposal.md) | 무엇을 승인받는지, 기존 승인이나 전용 신청이 있는지 |
| 다른 부서에서 결과 받기 | [업무 협조](guides/company/work-cooperation.md) | 상대가 해야 할 일과 필요한 결과물 |
| 경과·결과 공유 | [업무 보고](../../work-report/SKILL.md) | 독자가 확인할 결과·진행 단계와 이번 판단 요청 |
| 비용 정산·지급 | [지출결의서](guides/company/expense-approval.md) | 누가 결제했고 지금 누구에게 지급하는지 |
| 인력 모집 또는 채용 예정자 품의 | [채용 요청서](guides/company/recruitment-request.md), [채용 품의](guides/company/hiring-approval.md) | 모집을 시작하는 단계인지 채용 예정자와 조건이 정리된 단계인지 |
| 근태 일정·실제 결과·원신청 취소 | [근태 서식 목록](guide-index.md#근태) | 계획·실제 근무·취소 중 무엇인지, 원신청 종류와 적용 대상 |
| 개별 고객 문제나 의견 공유 | [소비자 클레임 발생서](guides/company/consumer-claim.md), [VOC 리포트](guides/company/voc-report.md) | 발생·초기 대응을 기록하는지, 수집한 의견과 개선 상태를 정리하는지 |

## 언제 다시 질문하나요?

업무 메모와 이미 입력한 값을 먼저 대조합니다. 각 서식의 질문과 사례를 참고해 다음 상태에 맞춰 진행합니다.

| 입력 상태 | AI가 할 일 |
|---|---|
| 작성에 필요한 핵심 정보가 충분함 | 이미 답한 내용을 다시 묻지 않고 작성합니다. 조건부 첨부나 시스템 계산처럼 작성자가 화면에서 대조할 값은 확인사항에 둡니다. |
| 서식 선택, 승인 범위, 날짜, 금액, 대상자, 원신청 또는 필수 입력을 바꾸는 공백이나 충돌이 있음 | 답에 따라 달라지는 부분을 짧게 설명하고 질문을 묶습니다. 예를 들어 “기안에는 2명, 근거표에는 3명입니다. 이번 승인 요청의 총인원은 몇 명인가요?”처럼 묻습니다. 답을 받으면 달라진 항목과 연관된 합계·본문만 다시 대조한 뒤 작성합니다. |
| 핵심 답이 없고 사용자가 확인 전 초안을 원함 | 출력 앞에 `확인 전 초안`을 표시합니다. 확정된 부분을 작성하고, 해당 칸에는 `확인 필요`와 확인할 근거를 남깁니다. 금액·승인·동의·실행을 추정해 확정하지 않습니다. |

질문은 문서의 결정에 필요한 만큼만 합니다. 질문의 답이 별도 화면의 선택값이나 조건에 따라 달라지면 필요한 입력 항목이나 선택지만 확인합니다. 실제 화면에서 확인한 값과 제약을 우선합니다. 계좌번호·개인 연락처·동의 선택은 작성자가 네이버웍스에서 직접 입력하도록 안내합니다.

## 결재자가 처음 읽는 순서

제목은 `대상 + 이번 요청 또는 핵심 결과`로 씁니다. 첫 문장에 읽는 사람이 결정하거나 실행할 일을 적습니다. 공유만 하는 보고라면 핵심 결과와 판단 요청 유무를 먼저 밝힙니다. 이어서 판단에 필요한 근거와 범위, 확인할 조건, 승인이나 회신 이후의 담당·기한을 적습니다. 아직 합의하지 않은 일정은 희망 또는 예정으로 표시합니다.

| 서식 | 첫 문단 또는 핵심 입력 | 이어서 확인할 내용 |
|---|---|---|
| 업무 보고 | 결과·진행 상태와 판단 요청 유무 | 기간·집계 기준·근거 → 남은 조치와 담당·일정 |
| 업무 기안 | 승인받을 결정·범위·필요 시 금액 | 현황과 선택 근거 → 실행 조건 → 승인 후 일정·담당 |
| 업무 협조 | 요청할 행동이나 받을 결과물·희망 기한 | 대상과 자료 → 회신 방법 → 합의된 일정 |
| 지출결의서 | 지급 형태, 목적, 지급·정산 대상 | 품목·수량·부가세 포함 금액 → 증빙 → 필요한 지급일·계좌 확인 |
| 인사·근태 신청 | 신청 구분, 대상, 적용일 또는 기간 | 실제 입력란의 조건과 사유 → 첨부·원신청·본인 확인 |
| 경위·시말·클레임·VOC | 사건·접수 또는 집계의 핵심과 현재 상태 | 확인한 사실과 근거 → 실제 조치 → 미정 사항과 후속 확인 |

같은 목적의 문서는 위 정보의 순서와 용어를 맞춥니다. 금액에는 통화·부가세·합계 기준을, 건수에는 집계 범위와 기준 시점을 적습니다. 원인이나 영향이 확인 중이면 그 상태를 표시합니다. 작성 화면에 별도 칸이 있는 정보는 그 칸에 입력하고, 본문에는 판단에 필요한 맥락을 더합니다. 자유 본문이 없는 서식은 실제 입력 칸과 작성자 확인으로 구성합니다.

거래 행이 있는 서식은 품목·수량·행 금액과 합계를 증빙에 대조합니다. 취소·환불·증빙 미확인 건이 합계에 영향을 주면 적용한 집계 기준과 확인할 차이를 표시합니다. 선행 승인과 이번에 요청하는 변경 범위, 실제 연결된 첨부와 연결할 자료를 구분합니다.

## 작성 화면의 각 칸으로 옮길 수 있게 출력합니다

1. **입력값**에는 문서 제목과 실제 항목명을 씁니다. 입력 칸에 들어갈 텍스트, 화면에서 선택할 값, 달력에 넣을 날짜, 표의 열과 행을 구분합니다. 사용자 제공 수치·단위·분모·합계를 대조합니다. 화면에서 직접 확인해야 하는 민감 정보나 본인 동의는 입력 방법만 남깁니다.
2. **자유 본문**은 해당 서식에 본문 칸이 있을 때만 씁니다. 작성 화면에 붙여 넣을 본문만 출력합니다. HTML을 요청하면 코드블록 하나에 본문만 넣고, 일반 텍스트는 그대로 붙여 넣을 수 있게 짧은 소제목과 문단으로 정리합니다.
3. **작성자 확인**에는 실제 첨부·연관문서·결재선, 조건부 입력·시스템 계산·본인 동의처럼 작성자가 확인할 작업을 남깁니다. 승인·지급·근태 반영은 각각 해당 기록이나 화면에서 확인합니다.

HTML을 작성할 때는 [공통 디자인 가이드](../../work-report/references/design.md)와 [HTML 본문 기본틀](../../work-report/assets/report-body.html)을 사용합니다. 바깥 `div`에 기본 글꼴 `font-family:sans-serif`를 지정합니다. 서식의 목적에 맞는 소제목으로 바꾸고 해당 없는 절과 작성 안내를 지웁니다.

## 전달 전에 확인합니다

- 제목과 첫 문단에서 결재자가 판단하거나 확인할 일을 찾을 수 있나요?
- 금액·건수·기준일이 표와 근거에 맞고, 결재 뒤에 할 일의 담당·기한과 확인 상태가 드러나나요?
- 실제 입력값, 붙여 넣을 본문, 작성자 확인이 구분되고, 첨부·연관문서가 실제 연결 상태대로 표시됐나요?
- HTML을 적용했다면 작성자가 Editor에서 제목·글꼴·줄바꿈·표·링크를 확인할 수 있나요?

자료의 설명은 작성 근거로 사용합니다. 가이드의 예시를 회사 승인, 지급 일정, 근태 적용이나 내부 의무로 해석하지 않습니다. 실제 작성 화면에 나타나는 조건과 가이드의 확인 범위가 다르면 그 차이와 필요한 확인만 명시합니다.
