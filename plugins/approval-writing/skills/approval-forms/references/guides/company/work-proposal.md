# 업무 기안 작성 가이드

> 공개용 작성 예시입니다. 입력 항목·선택지·절차는 예시이며, 실제 작성 화면과 소속 조직의 기준을 따릅니다. 사례의 조직·인물·수치·일정은 가상입니다.

새 업무를 시작하거나 기존 승인 범위를 바꾸기 위해 결정을 받을 때 사용합니다. 예산, 계약, 채용 등 전용 서식이 있는 안건은 담당 부서가 안내한 양식을 먼저 확인하세요.

## 작성 전에 준비하기

승인받을 대상과 범위, 결정이 필요한 이유, 근거 자료를 모읍니다. 비용이 들면 수량, 단가, 부가세 포함 여부, 합계와 재원을 확인합니다. 승인 뒤 할 일과 이미 합의한 담당·일정이 있다면 기록을 함께 준비합니다.

| 요청 상황 | 메모에 없으면 먼저 확인할 질문 | 본문에 남길 내용 |
|---|---|---|
| 새 업무나 시험을 시작 | 어떤 대상에 어디까지 적용하나요? 승인 후 실제로 시작할 수 있나요? | 승인 범위, 실행 전 조건, 결과를 확인할 방법 |
| 기존 승인 범위를 변경 | 무엇까지 승인됐고 이번에 달라지는 항목은 무엇인가요? | 기존 승인과 변경 요청, 변경 사유와 추가 영향 |
| 비용·구매·계약 포함 | 승인받을 금액과 비교·견적 기준은 무엇인가요? 전용 신청 경로가 있나요? | 금액·세금 기준·일정, 판단에 필요한 조건과 근거 |
| 여러 부서의 실행이나 운영 전환 | 어느 부서가 영향을 받고, 어떤 협의가 끝났나요? 실행을 시작하거나 멈출 조건은 무엇인가요? | 협의 상태, 단계별 담당·기한, 실행·보류·재상신 조건 |

결과 공유만 필요하면 [업무 보고](../../../../work-report/SKILL.md), 다른 부서의 자료나 작업이 필요하면 [업무 협조](work-cooperation.md)를 검토합니다. 승인된 비용의 지급을 요청할 때는 [지출결의서](expense-approval.md)의 지급 유형을 확인합니다.

## 작성 화면에 넣기

1. **제목**에 승인받을 일을 한 줄로 적습니다. 예를 들어 `포장 작업대 재배치 시범 운영 승인 요청`으로 적습니다.
2. **소속 부서**에서 작성 조직을 확인합니다.
3. **기안 내용** 첫 문단에 결정받을 범위와 조건을 적습니다. 이어서 현황과 추진 이유, 선택 근거, 비용·일정, 승인 후 조치를 필요한 만큼 정리합니다. 협의가 남은 항목에는 확인 중인 내용과 결정 시점을 표시합니다.
4. **파일 첨부**에 판단 근거가 되는 견적, 배치안 또는 비교 자료를 실제로 연결합니다.
5. **연관문서**에는 연결할 이전 기안이나 승인 문서가 있을 때 등록하고, 이번에 달라지는 범위를 본문에 적습니다.

## 복합 기안의 본문 구성

| 절 | 결재자가 확인할 내용 |
|---|---|
| 승인 요청 | 이번에 승인할 안, 적용 대상·범위·기간, 지출 한도와 세금 기준, 결정 희망일. 기존 승인이 있으면 이번 변경분을 밝힙니다. |
| 현황과 추진 근거 | 문제의 범위와 기준 시점, 지금 결정해야 하는 이유, 판단에 쓰는 기록·견적·협의 결과. 자료에 없는 효과는 목표나 검증 항목으로 적습니다. |
| 대안 비교와 추천 | 비교할 수 있는 대안의 비용·범위·일정·제약을 같은 기준으로 제시합니다. 범위나 계약 기간이 다르면 표에 적습니다. 추천안이 어떤 조건에서 적합한지 설명합니다. |
| 비용과 승인 조건 | 수량 × 단가, 추가비·세금·합계, 재원 확인 상태와 지출 한도. 진행 조건과 보류·재협의 기준을 나눕니다. |
| 승인 후 실행 | 단계별 담당·기한·완료 기준, 점검 또는 결과 공유 방법. 예정된 실행과 이미 완료한 일을 구분합니다. |

모든 절을 채우기보다 판단에 필요한 항목을 씁니다. 사전 협의 중인 내용은 합의로 적지 않습니다. 기존 승인에 없는 추가 지출이나 운영 범위는 이번 승인 요청에서 명시합니다. 비용·범위·일정이 다른 여러 안은 비교표로, 승인 뒤 인수인계가 필요한 안은 실행표로 정리합니다. [공통 디자인 가이드](../../../../work-report/references/design.md)

업무 기안 본문의 대제목과 소제목은 각각 한 줄에 두고 제목 글자에 밑줄을 적용합니다. 같은 항목에서 설명 주제가 바뀌면 한 번 줄을 바꿔 새 문단을 시작합니다. 같은 설명이 이어지는 문장은 한 문단에 두고, 문단 사이의 간격은 여백으로 맞춥니다.

### 실행 계획의 하위 항목

실행 계획에 비용 산정과 후속 조치가 모두 있으면 `① 이용료 산정`, `② 승인 후 진행`처럼 같은 단계의 소제목을 각각 한 줄에 둡니다. 번호는 소제목에 실제 문자로 입력하고 설명이나 표는 다음 줄에 놓습니다. 한 가지 내용이면 번호를 붙이지 않아도 됩니다.

- **① 이용료 산정**에는 적용 수량·단가·기간을 밝히고, 지원이나 계약 조건에 따라 금액이 달라지면 비교표로 제시합니다. 세금·재원 등 확인이 남은 조건은 표 아래에 적습니다.
- **② 승인 후 진행**에는 작성 부서가 할 일, 관계 부서와 협의할 내용, 착수 조건과 결과 공유 시점을 적습니다. 담당이나 일정이 정해지지 않았으면 협의 또는 확인할 사항으로 표시합니다.

사용자가 해당 문서의 글자 크기·줄 높이·문단 간격·제목 표시를 지정했거나 직접 맞춘 서식을 보존하라고 요청한 경우 그 지정을 아래 기본값보다 우선합니다. 예를 들어 13px·추가 문단 여백 없음으로 지정한 문서를 14px·행간 1.7·문단 아래 10px로 임의 변경하지 않습니다. 작성·검수할 때 사용자 지정값과 기본값을 구분합니다.

## AI로 초안 요청하기

아래 코드블록을 복사해 회사에서 허용한 AI에 붙여 넣고, 아는 항목에 메모를 채웁니다. 플러그인이 설치되어 있으면 `$approval-forms 업무 기안으로 작성해 주세요`와 업무 메모를 입력해도 됩니다.

```text
네이버웍스 업무 기안 초안을 작성해 주세요.
이번에 승인받을 결정과 범위: [대상, 수량, 기간, 결정 희망일]
기존 승인과 이번 변경분: [선행 문서와 승인 범위, 달라지는 항목]
현황과 근거: [확인된 문제, 기준일, 수치의 범위, 확인 자료]
비교한 대안과 추천안: [각 안의 적용 범위, 비용, 장단점, 추천 이유]
비용과 조건: [수량·단가·부대비·세금·합계·한도·재원, 확인 여부]
사전 협의와 승인 후 계획: [협의 상태, 단계별 담당·기한, 착수·보류 조건, 결과 확인]
파일 첨부와 연관문서: [실제 연결 여부 또는 작성자가 연결할 자료]

이미 제공한 내용은 다시 묻지 말고, 결정에 영향을 주는 공백이나 충돌만 확인해 주세요.
가. 화면 입력값, 나. 기안 내용, 다. 작성자 확인으로 나눠 주세요.
별도의 인사말은 생략하고, 첫 문단에 ‘○○ 승인을 요청드립니다’처럼 승인 대상과 범위를 적어 주세요. 승인 조건이나 추가 결정이 남았다면 ‘승인 후 견적을 확인하여 최종 비용을 보고드리겠습니다’처럼 다음 조치를 밝혀 주세요.
본문은 합니다체로 씁니다. 같은 판단에 필요한 문장은 한 문단에 이어 쓰고, 배경·비용 조건·후속 조치처럼 주제가 바뀔 때 새 문단을 시작해 주세요. 같은 기준으로 비교할 대안·비용 조건은 비교표로 보여 주세요. 단계별 담당과 기한을 나란히 확인해야 하면 실행 일정표를 넣어 주세요.
큰 항목에 여러 주제가 있으면 요지를 한두 문장으로 적고, 같은 단계의 소제목 앞에 ①, ②를 실제 문자로 넣어 주세요. 실행 계획에 이용료 산정과 승인 후 조치가 모두 있으면 ‘① 이용료 산정’, ‘② 승인 후 진행’을 각각 한 줄에 두고 설명을 이어 주세요. 순서가 있는 절차는 번호 목록, 순서와 무관한 조건은 글머리표를 사용해 주세요.
본문의 대제목과 소제목은 한 줄에 두고 제목 글자에 밑줄을 적용해 주세요. 같은 항목에서 설명 주제가 바뀌면 새 문단을 시작하고, 같은 설명이 이어지는 문장은 한 문단에 두세요.
HTML은 본문만 코드블록 하나로 주세요. 문서별로 지정한 서식을 우선하고, 별도 지정이 없으면 대제목은 16px 굵게(첫 위 여백 0px, 이후 24px, 아래 8px), 하위 제목은 14px 굵게(위 12px, 아래 4px), 본문은 14px·행간 1.7·문단 아래 10px을 적용해 주세요. 표는 내용에 맞는 너비(`width:auto;max-width:100%`)로 시작해 주세요.
작성 부서가 제안하는 조치는 ‘○○하고자 합니다’, 승인받을 결정은 ‘○○ 승인을 요청드립니다’로 적어 주세요. 현재 운영, 제안, 승인 후 조치를 구분하고 관계 부서의 담당이 합의 전이라면 협의할 행동으로 써 주세요. 흐름도를 넣을 때는 본문과 단계명·담당·착수 조건·예외 처리 기준을 맞춰 주세요.
확인하지 못한 비용·협의·승인·실행은 상태를 밝혀 주세요.
```

## 간단한 기안 예시 · 가상 작업대 시범 운영

메모에서 승인 요청은 작업대 1대의 5일간 시범 재배치이고, 상시 적용은 결과를 본 뒤 검토하는 것으로 확인했습니다.

| 입력 칸 | 작성값 |
|---|---|
| 제목 | 포장 작업대 재배치 시범 운영 승인 요청 |
| 소속 부서 | 업무지원팀(가상) |
| 파일 첨부 | 없음 |
| 연관문서 | 없음 |

**기안 내용**

> **승인 요청**
>
> 11월 23일부터 27일까지 포장 작업대 1대를 재배치해 시범 운영할 수 있도록 승인 요청드립니다.
>
> **추진 근거와 조건**
>
> 포장과 출고가 겹치는 시간대의 이동 동선을 확인하기 위해 기존 작업대를 이용합니다. 업무지원 담당이 작업대 위치와 통행에 지장이 없는지 확인한 뒤 옮깁니다.
>
> **승인 후 조치**
>
> 업무지원 담당이 시범 기간 중 변경 전후 동선을 비교하고 11월 30일에 결과를 공유할 예정입니다. 상시 적용 여부는 시범 결과를 바탕으로 검토합니다.

**HTML 입력이 필요한 경우**　`기안 내용`의 HTML 탭에서 해당 본문을 아래 코드로 교체하고 Editor로 전환합니다. 같은 원고를 Editor에 다시 붙여넣지 않습니다. 제목과 문단이 한 번씩만 표시되는지, 문단 사이 간격과 표가 바르게 표시되는지 확인합니다. 제목·부서·첨부 상태는 각각의 입력 칸에서 지정합니다.

```html
<div style="font-family:sans-serif;font-size:14px;line-height:1.7;color:#30343B;">
  <h3 style="font-size:16px;font-weight:700;margin:0 0 8px;text-decoration:underline;">승인 요청</h3>
  <p style="margin:0 0 10px;">11월 23일부터 27일까지 포장 작업대 1대를 재배치해 시범 운영할 수 있도록 승인 요청드립니다.</p>
  <h3 style="font-size:16px;font-weight:700;margin:24px 0 8px;text-decoration:underline;">추진 근거와 조건</h3>
  <p style="margin:0 0 10px;">포장과 출고가 겹치는 시간대의 이동 동선을 확인하기 위해 기존 작업대를 이용합니다. 업무지원 담당이 작업대 위치와 통행에 지장이 없는지 확인한 뒤 옮깁니다.</p>
  <h3 style="font-size:16px;font-weight:700;margin:24px 0 8px;text-decoration:underline;">승인 후 조치</h3>
  <p style="margin:0 0 10px;">업무지원 담당이 시범 기간 중 변경 전후 동선을 비교하고 11월 30일에 결과를 공유할 예정입니다. 상시 적용 여부는 시범 결과를 바탕으로 검토합니다.</p>
</div>
```

**작성자 확인**　재배치 대상이 1대인지, 시험 기간과 결과 공유 일정이 협의된 내용인지 대조합니다. 승인 후에 실행할 일을 완료로 기록하지 않습니다.

## BEST 사례 · 시범 범위 변경과 장비 임차 승인

아래 일정·금액·조직·첨부는 가상입니다. 기존 승인을 변경하는 기안에서 결재자가 기존 범위, 대안, 지출 한도와 실행 조건을 한 문서에서 확인하는 예시입니다.

### 가. 화면 입력값

| 입력 칸 | 작성값 |
|---|---|
